# First Tech Blog Post — The Boundary Trap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the first real technical post, “Hermes AI Agent Series: The Boundary Trap,” as a native page with a generated cover, inline figures, series metadata, and a wide homepage highlight card.

**Architecture:** Extend the existing draft → `sync-posts.mjs` → `src/data/post/` pipeline rather than hand-writing generated content. Add inline-image copying/rewriting and asset-aware hashing to the sync script, generate a raster cover from a tracked SVG through the existing `prepare-assets.mjs` Sharp pipeline, and add a `featured` mode to the existing homepage blog widget.

**Tech Stack:** Astro 7, Tailwind CSS v4, TypeScript 5.9, Sharp, js-yaml, limax, Node 22 `node:test`, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-24-first-tech-blog-design.md`

## Global Constraints

- Site: `https://pengzhao-ai.github.io`, `base: '/'`, `trailingSlash: true`.
- Post URL pattern is `/%slug%`; this post is `/agent-docker-path-trap/`.
- Node `>= 22.22.3`. No new runtime dependencies; Sharp, js-yaml, and limax are already present.
- `src/data/post/` is generated by `scripts/sync-posts.mjs`; never edit it by hand.
- `artifacts/blog/` holds tracked text sources. Binary originals under `artifacts/` stay out of git; committed images live under `src/assets/images/` and must contain no EXIF.
- `Image.astro` requires an explicit `alt`; every card/hero image declares `width`, `height`, `widths`, `sizes`, and `format="webp"`.
- All internal links go through `getPermalink`/`getBlogPermalink`; never hand-write root-relative hrefs.
- Use the site tokens (`panel`, `tile`, `tile-flush`, `text-heading`, `text-muted`, `text-primary`), Space Grotesk for headings, JetBrains Mono for technical labels.
- Prettier: single quotes, print width 120, `prettier-plugin-astro`.
- **Do not commit or push.** The owner has not authorized it. Each task ends with a working-tree checkpoint (`git diff --check` and `git status --short`), not a commit.

## Review Focus

1. **An image reference inside a fenced code block** must not be copied or rewritten. → Task 1 collector test.
2. **A referenced figure missing on disk** must fail the sync with exit code 2 and name the file, not silently write a broken post. → Task 1 `planSync` test.
3. **A figure edit without a Markdown edit** must trigger an `update` and copy the new bytes; it must not report `skip`. → Task 1 asset-hash test.
4. **`~/assets/...` body-image paths must resolve in the Astro build.** The built post HTML must contain emitted asset URLs, not the literal `~/assets` path. → Task 4/5 build check.
5. **A post with no cover or no series fields** must render the homepage and post page without an image or label and without errors. → Task 5 build check (the existing “Why this site exists” post).
