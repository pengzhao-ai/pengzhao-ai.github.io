## 1. Intent

Publish the first real technical post, **“Hermes AI Agent Series: The Boundary Trap,”** as a native page of the
personal site, with a wide thumbnail-led highlight on the homepage. The existing “Why this site exists” post
remains as the older entry. This is the first post in the Hermes AI Agent series; future posts may cover optics,
hardware, or other topics.

The article is already written and technically reviewed. This work is synthesis and presentation, not a rewrite.

## 2. Goals

1. The post is live at `/agent-docker-path-trap/` with its full body, both figures, captions, code blocks,
   metadata, related posts, RSS entry, sitemap entry, and structured data.
2. A real 16:9 cover image exists and drives the homepage card, the post hero, the Open Graph/Twitter card, and
   the `BlogPosting` image.
3. The homepage promotes the newest post in a wide featured card and lists older posts as compact rows.
4. The post is categorized `AI` with tags `AI`, `System Design`, `Engineering`, and carries the series metadata
   `Hermes AI Agent`, order `1`.
5. The blog sync pipeline copies inline figures into the site asset tree and rewrites their Markdown paths, so
   adding a post with figures is still “one draft plus one sync command.”
6. All existing content, image-privacy, idempotence, and drift-detection invariants continue to hold.

## 3. Non-goals

- A separate repository or GitHub Pages site for blog posts. Blog posts are native pages of this site.
- A CMS, comments, analytics account, newsletter form, or contact form.
- Rewriting the article’s voice, structure, or claims. Only figure paths and figure captions are added.
- A table-of-contents sidebar. The article already contains its own “What this post covers” list.
- New runtime dependencies. `sharp`, `js-yaml`, and `limax` are already present.
- Committing or pushing the changes. The owner has not asked for that.

## 4. Constraints

- Astro 7 + AstroWind, fully static, deployed to GitHub Pages from `main` by `.github/workflows/deploy.yml`.
- `src/data/post/` is generated by `scripts/sync-posts.mjs`; it is never edited by hand.
- `artifacts/blog/` holds tracked text sources. Binary originals under `artifacts/` stay out of git; committed
  images live under `src/assets/images/` and must carry no EXIF.
- `Image.astro` requires an explicit `alt`; card and hero images declare `width`, `height`, `widths`, `sizes`,
  and `format="webp"`.
- The site’s design tokens are used: `panel`, `tile`, `text-heading`, `text-muted`, `text-primary`, Space Grotesk
  for headings, JetBrains Mono for technical labels, and the existing light/dark palette.
- Node `>= 22.22.3`, Node’s built-in `node:test` runner; no test framework.
- Prettier: single quotes, print width 120, `prettier-plugin-astro`.

### 5.4 Sync pipeline extension

`scripts/sync-posts.mjs` gains four behaviors:

1. **Collect** Markdown image references outside fenced code blocks. Skip remote URLs, root-relative paths,
   `data:` URLs, fragments, and `~/` paths.
2. **Copy** each local reference to `src/assets/images/posts/<slug>/<basename>` and **rewrite** the reference to
   the `~/assets/images/posts/<slug>/<basename>` form.
3. **Fingerprint** the copied asset bytes as part of `sourceHash`, so changing a figure without changing the
   Markdown still triggers an `update` and re-copies the figure.
4. **Fail loudly** when a referenced figure is missing (exit code 2, skip that post, name the file) or when two
   different sources would collide on the same destination basename.

Astro’s content-image pipeline resolves the site’s `~/` Vite alias through the post file’s importer, so the
rewritten `~/assets/images/posts/…` body references are compiled to emitted asset URLs (or inlined data URIs for
small SVGs). The build verification checks that the literal alias does not survive in the HTML.

The existing H1 removal, frontmatter preservation, dry-run default, conflict detection, and orphan handling are
unchanged. The generated frontmatter preserves `series` and `seriesOrder` in a fixed key order.

### 5.5 Cover and thumbnail

A 1600 × 900 JPEG, generated from a tracked SVG source by `scripts/prepare-assets.mjs` using Sharp. The cover:

- uses the site palette (`#FAFAFC` page, `#0F172A` heading, `#2563EB` primary, `#7C3AED` accent, `#16A34A` /
  `#DC2626` for the success/failure states);
- carries a small mono series label `HERMES AI AGENT · 01`;
- shows the short title “The Boundary Trap” and the core visual: a **HOST** panel and a **CONTAINER** panel
  joined by a bind-mount line, with the same file visible in both;
- has safe margins so the 1200 × 626 Open Graph crop does not cut the meaningful content;
- is rendered through Sharp without metadata, satisfying the no-EXIF invariant.

The cover source is authored by the implementer from this design; the bundle has no cover. The SVG uses generic
`Helvetica, Arial, sans-serif` and `monospace` families because the site’s Space Grotesk / JetBrains Mono are
loaded by Astro’s Fonts API, not installed system-wide for Sharp. This matches the existing OG card and avoids a
silent font fallback.

The same JPG appears as the post hero, the homepage featured-card image, the Open Graph/Twitter image, and the
`BlogPosting` image.

The two inline figures remain SVG. They are diagrams, not photographs, and Astro passes SVG sources through
without transformation. The cover must be raster because the hero/OG code requests `webp`/`jpg` conversions,
which Astro refuses for SVG sources.

### 5.6 Detail page

`src/components/blog/SinglePost.astro` already renders the title, excerpt, date, author, category, reading time,
cover, prose, tags, share links, and related posts. The route already emits `BlogPosting` JSON-LD and OG/Twitter
metadata. Changes:

- add the two manifest captions as italic paragraphs immediately after their images **in the draft Markdown**.
  They are article content, copied unchanged by the sync; `SinglePost.astro` does not inject per-figure
  captions. The SVG titles show the same phrases inside the diagrams; the caption below is the visible,
  selectable text and the accessible description. If the duplication is unwanted, drop the caption paragraphs
  in the draft before syncing — no code change is required;
- render a small `SeriesLabel` above the title when `series` is present;
- keep the article body otherwise verbatim.

The article’s “What this post covers” anchor list is preserved. Astro’s heading slugger produces the same
GitHub-style anchors, so the links resolve without changes.

The figures keep their light canvas in both themes; the existing prose image styling (rounded corners, shadow)
frames them as diagrams. No dark-mode variant is generated.

### 5.7 Homepage

`BlogLatestPosts` gains an optional `featured` mode, enabled on the homepage:

- the newest post renders as a wide `FeaturedPost` card: 16:9 cover on the left, series/date/title/excerpt/tags
  and a “Read the post” link on the right; stacked on mobile;
- older posts render in `CompactPostList` as compact rows with an optional small thumbnail, title, date,
  category, and reading time;
- the existing `Grid` rendering remains the default for any other caller.

A new `tile-flush` utility provides the `tile` surface without padding so the image can sit flush against the
card edge. The featured card handles a missing image gracefully; the older “Why this site exists” post has no
cover and renders as a text row.
